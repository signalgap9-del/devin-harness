# SEO operations for your-product.com

This repo's SEO surface is **static files + a few env vars**, not a CMS.
Everything below is load-bearing — check it before assuming "SEO is broken".

## The indexing pipeline (verify in this order)

1. `apps/web/public/sitemap-static.xml` — served through the /sitemap.xml
   route. The hand-curated head is for ONE-OFF pages only; slug families
   and static marketing routes are enforced/generated by
   `build-sitemap.mjs` at build time. New slug family → register its data
   file there, never hand-add URL blocks.
2. `robots.txt` — served via a route (not public/), already declares
   `Sitemap:`. Don't break it.
3. `llms.txt` — AI-crawler surface; add notable pages there too.
4. **IndexNow** — `node ops/seo/indexnow.mjs` pushes all sitemap URLs to
   Bing/Yandex/Seznam via separate endpoints. Naver is deliberately
   excluded — do NOT switch to api.indexnow.org, which broadcasts to
   participating engines incl. Naver. Google doesn't read IndexNow.
   Key file `/6f8f6711c005411f942f0a016e9055a2.txt`
   is whitelisted in the geo gate (`ALWAYS_ALLOWED_PATHS`). It now runs
   AUTOMATICALLY at the end of every successful deploy (deploy-wrap.mjs,
   best-effort) — manual runs are only needed for URL changes that ship
   outside a deploy (e.g. KV-published posts).
5. **Sitemap entries are generated, not hand-maintained.** Slug families
   (`/for/*`, `/models/*`, `/feed/*`, `/prompts/*`, `/edit/*`, `/blog/*`,
   `/docs/*`) emit from their data files in `build-sitemap.mjs`; the
   builder hard-fails if a parsed slug is missing or a static marketing
   route has neither an entry nor a reasoned `SITEMAP_EXCLUDE` line.
   Never hand-add `<url>` blocks for a slug family in
   sitemap-static.xml — they drift stale (burned 2026-10-31).
5. **Google** — no IndexNow support. `GOOGLE_SITE_VERIFICATION` env var
   renders a `<meta>` in root.tsx. If empty, verify Search Console via the
   linked GA4 property (`GA4_ID=G-NQYKEN9MZW`) — zero-deploy path.
   Submit the sitemap URL in GSC once verified.

## The geo gate kills traffic silently — check it first

`server/middleware/geo.ts` + `GEO_GATE=1` in prod. Any page/marketing push
into a country NOT in `ALLOWED_COUNTRIES` returns 403 — ads included.

- Sanctioned states stay blocked (provider/OFAC terms): SY, IR, YE, LY,
  SD, CU, KP, RU, BY, VE.
- `ALWAYS_ALLOWED_PATHS` exists because crawlers and verification files
  (robots/sitemap/llms/IndexNow key/TikTok verify) must be fetchable from
  anywhere.
- **A matching WAF custom rule may exist on the zone** (per the comment in
  geo.ts). If a region still 403s after a list update, the zone rule is
  blocking before the worker — dashboard-only fix, and page_view won't
  even record the hit.
- `ALLOWED_CALLING_CODES` must grow with ALLOWED_COUNTRIES (phone OTP
  validation uses it).
- `analytics` runs before `geoGate`, so worker-level 403s DO leave
  page_view rows. Region with zero rows = traffic never arrived
  (ads/indexing/WAF), not "blocked".

## Copy gate — read AGENTS.md "Copy doctrine"

Every public page is audited by `ops/verify/copy-audit.mjs` at deploy
(sitemap-wide, web-grounded). Mechanism-backed claims only; slop blocks
deploys. `ops/verify/copy-accept.json` holds pre-approved lines.

## Locale policy (owner call 2026-10)

English-only today; **ja + es + de are the planned additions** (anime/
cosplay demand in JP, LatAm/ES, DE). **ko + zh are excluded**: KR is outside
ALLOWED_COUNTRIES (geo gate 403s it) and zh needs a separate Baidu-first
strategy — hreflang doesn't reach Baidu. Every page already emits
en + x-default alternates: in-page via `pageAlternates()` in root.tsx,
sitemap-wide via `build-sitemap.mjs` `HREFLANG_LOCALES`. Adding a locale =
dict + `LOCALES` entry + `HREFLANG_LOCALES` entry — alternates appear
automatically on localizable paths. Translate only pages that show
impressions/clicks first; don't bulk-translate unproven copy.

## Per-locale checklist for a new market

- [ ] copy file exists in `app/i18n/copy/` and satisfies `LandingCopy`
- [ ] `:locale` route accepts the locale (check the allowlist in
      routes/marketing)
- [ ] sitemap `<loc>` + hreflang cluster (incl. `x-default`)
- [ ] `<html lang dir>` correct (ar → `dir="rtl"`)
- [ ] localized `<title>`/description render — `curl -s /$locale/ | grep`
- [ ] country ∈ `ALLOWED_COUNTRIES` + calling code ∈ `ALLOWED_CALLING_CODES`
- [ ] IndexNow ping after deploy
- [ ] page_view rows appear for that country within days — if zero and ads
      are running, check the zone WAF rule

## Bots / junk traffic

`server/middleware/bots.ts` sheds scraper UAs and cf.threatScore ≥ 50 on
HTML GETs before analytics. Good crawlers are allowlisted — extend
GOOD_BOT_UA, never delete. Zone-level blocking (Bot Fight Mode, WAF rules,
managed challenge) is stronger because it stops requests before worker
billing — needs dashboard/API perms the worker token lacks.
